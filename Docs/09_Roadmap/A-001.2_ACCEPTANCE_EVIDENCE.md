**Checkpoint:** A-001.2 — Bundled Python sidecar and installed lifecycle
**Accepted:** 2026-08-25
**Starting commit:** `88638810bf90f47c54067604daa77fb3f414eb34`

## Accepted outcome

- The Windows x64 desktop build creates a target-triple-named, one-file Python
  sidecar from a fully hash-locked dependency set.
- Tauri owns a lazy, long-lived sidecar process and communicates through the
  closed JSON-lines readiness protocol without exposing shell permissions to
  the webview.
- Development and release builds use the same bundled-sidecar path. There is
  no runtime fallback to a checkout or system Python.
- Correlation, identity, application version, protocol version, timeouts,
  process failure, restart, environment reduction, and safe error collapse are
  enforced at the Rust trust boundary.
- The release system treats the sidecar as a fifth checksummed artifact and
  validates its generated identity manifest before staging it.
- The NSIS installer contains both the sidecar and its generated manifest and
  removes both during uninstall.
