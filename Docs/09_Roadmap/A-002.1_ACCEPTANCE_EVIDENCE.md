# A-002.1 acceptance evidence

**Checkpoint:** A-002.1 — SQLite prompt-library persistence foundation
**Accepted:** 2026-08-31
**Starting commit:** `34b9a8974600f3ab2846f5e34aada9d4e4ec7501`

## Accepted outcome

- Rust resolves Tauri's per-user `app_data_dir` and passes only that trusted
  directory to the frozen sidecar after clearing its inherited environment.
- Python appends the fixed `prompt-library.sqlite3` filename. The database is
  never created in the repository, current working directory, or installation.
- SQLite schema version 1 has an explicit forward migration from an empty
  version-0 database, modern transaction control, foreign-key enforcement,
  integrity/schema/relationship validation, and bounded lock waits.
- Future, corrupt, unmanaged, incomplete, relationship-invalid, and unavailable
  databases fail safely without deletion, replacement, rename, truncation,
  downgrade, or automatic repair.
- Projects and project-owned prompts can be created and listed through durable
  repositories and services, then reopened after process/application restart.
- The webview exposes five fixed Tauri commands with no shell or filesystem
  permission. Rust maps them to five fixed sidecar commands and independently
  validates correlation, identities, versions, capabilities, UUIDs, timestamps,
  value bounds, collection bounds, and project ownership.
- The desktop now opens the local library automatically and provides usable
  project creation/selection and prompt creation/listing views.
