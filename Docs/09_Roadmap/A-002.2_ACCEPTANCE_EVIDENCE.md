**Starting commit:** `5cc296fe00b516e75b037d55f4a50f409f002a71`

## Accepted outcome

The desktop prompt library now supports the complete bounded local management
lifecycle:

- create, select, edit, and delete prompts within a project;
- delete a project and all of its prompts transactionally;
- organize prompts with one category, bounded unique tags, and ordered typed
  blocks;
- add, remove, enable, disable, and reorder prompt blocks;
- search within the selected project across title, category, tags, and block
  content; and
- retain the managed state across application restarts in the versioned SQLite
  database under the per-user app-data directory.

The existing SQLite schema version remains `1`. A-002.1 already persisted the
category, tag, block, ordering, and ownership values required by this
checkpoint, so no migration was necessary.

## Desktop IPC boundary

The fixed allowlist now contains ten commands:

1. `application.readiness`
2. `library.projects.list`
3. `library.projects.create`
4. `library.projects.delete`
5. `library.prompts.list`
6. `library.prompts.create`
7. `library.prompts.get`
8. `library.prompts.update`
9. `library.prompts.delete`
10. `library.prompts.search`

Mutating commands require exact project/prompt ownership. Delete commands also
require `confirm: true`. The bridge rejects unknown fields, malformed UUIDs,
empty required text, oversized values, duplicate tags, invalid block types,
invalid block ordering, and ownership mismatches before persistence.

The management bounds are:

- category: at most 80 characters;
- tags: at most 10 unique values, each at most 32 characters;
- blocks: at most 12 ordered values;
- block content: at most 2,000 characters per block and 12,000 characters in
  total; and
- search query: at most 120 characters.

Search is project-scoped, case-insensitive, deterministic, and local-only.
Results are ordered consistently and never cross project ownership boundaries.
